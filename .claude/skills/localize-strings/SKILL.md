---
name: localize-strings
description: Fill the AI context and AI translations after adding, changing or removing a string in src/locales/en_US.ts. Use whenever a change touches en_US.ts, before committing it.
---

<goal>Every string added or changed in `src/locales/en_US.ts` ships with its context entry and its AI translation for every locale, generated by the repo scripts and committed with the code that uses it.</goal>

<rules>
<rule id="when">Applies to any change that adds, edits or removes a key in `src/locales/en_US.ts`. Also run it after moving or renaming the code that uses a key: the context hash covers the usage files, so a key whose usage sites changed is described and translated again.</rule>
<rule id="one-command">Run `npm run localize:ai` from the repo root. It regenerates `src/locales/strings/enUS.json`, then runs `localize:context` and `localize:translate --locale all`. Both steps are incremental: unchanged keys cost no model calls, and a rerun retries only what is still missing.</rule>
<rule id="never-hand-edit">Never hand-edit `src/locales/strings-ai/*.json`, `src/locales/context/enUS.context.json`, `src/locales/context/translateState.json` or `src/locales/strings/enUS.json`. They are generated. To change an output, change the English value or its usage code and rerun. Never translate a string yourself.</rule>
<rule id="same-commit">Commit the generated files in the same commit as the `en_US.ts` change and the code that uses the key.</rule>
<rule id="claude-backend">Claude runs through `claude -p` on the operator's subscription. When `ANTHROPIC_API_KEY` is set the scripts bill the Anthropic API instead, so unset it (`env -u ANTHROPIC_API_KEY npm run localize:ai`) unless the operator approved API spend.</rule>
<rule id="jev-optional">`TYPESAFE_API_KEY` enables the Jev reuse screen and the meaning and language gate. Without it the run prints `TYPESAFE_API_KEY is not set: skipping the Jev checks.` and still completes; say in the PR that the Jev checks were skipped.</rule>
<rule id="no-compare">Do not run `localize:compare`. It is a one-time evaluation of AI against human translations, not part of adding strings.</rule>
</rules>

<steps>
<step n="1">Make the `en_US.ts` and code changes.</step>
<step n="2">Run `npm run localize:ai`. The context step prints `<n> keys, <n> up to date, <n> new or changed`; the translate step prints one `<locale>: <n> translated, ...` line per locale followed by any problems, then a token summary per step.</step>
<step n="3">Check the translate summary. A `gate:` line is a Jev flag: report only, the value is kept. Any other indented line under a locale is a value left empty after the retry (the app falls back to English). Rerun once; list any key still empty in the PR body.</step>
<step n="4">Review `git diff src/locales`: the new keys have a context entry and a value in each `strings-ai/*.json` file, and only the keys you touched changed.</step>
<step n="5">Commit the generated files with the change. In the PR body, report the `Claude <model>: ... calls, input ..., output ...` and `Jev: ...` lines from both steps, plus any gate flags and empty values.</step>
</steps>

<edge-cases>
<case name="Key removed">The rerun drops the key from the context store and every `strings-ai` file. Commit those deletions.</case>
<case name="Unrelated keys changed">A key you did not touch changed because its usage files changed in your diff. That is expected; commit it.</case>
<case name="Script missing">If `scripts/localizeTranslate.ts` is not on the branch, the AI pipeline has not landed there: run `npm run localize` only.</case>
<case name="Step fails">A non-zero exit stops the chain. Read the error, fix the cause (missing `claude` CLI, network, a malformed `en_US.ts`), and rerun; finished keys are not redone.</case>
</edge-cases>
